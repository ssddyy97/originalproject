「確認してから保存する」だけでは、同時リクエストは防げない。

JPA 保存時に会議室単位の advisory transaction lock を取得し、PostgreSQL の排他制約で CONFIRMED の時間重複を拒否。競合はアダプターがドメイン例外へ変換し、HTTP 409 を返します。

04 / BUSINESS RULES

予約のルールを、明確に。

ドメイン・サービス・DB が、それぞれの責務を担当。

TIME VALIDATION

開始時刻 < 終了時刻

同じ時刻や逆転した期間は作成できません。ReservationPeriod と DB の CHECK 制約で検証。

NO OVERLAP

同じ会議室、重なる時間は不可。

CONFIRMED のみを対象に重複を確認。09:00–10:00 と 10:00–11:00 のような連続予約は可能です。

STATE TRANSITION

CONFIRMED → CANCELLED

キャンセルは削除ではなく状態変更。取り消した予約を再度取り消す操作はドメインが拒否します。

AVAILABLE AGAIN

取り消した時間を、もう一度。

CANCELLED は重複確認と DB の排他制約の対象外。同じ会議室・時間帯で新たに予約できます。

実装上の補足・発表時の説明ポイント

In-Memory 実装は保存先の差し替え例です。PostgreSQL と同等の永続性・同時実行制御は提供しません。再キャンセル時の IllegalStateException は専用の HTTP エラーマッピングが未実装です。上記の 409 は予約時間の競合に対する応答です。

空き状況の確認は予約枠の確保ではありません。最終的な予約可否は作成処理で判断されます。
